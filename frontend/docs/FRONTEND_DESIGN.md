# 前端设计说明

## 1. 产品方向

这是内部设备借还管理系统，采用克制的企业后台风格，不采用营销页面结构。信息层级优先顺序为：

1. 当前需要处理的申请和交接任务
2. 逾期、未归还等工作风险
3. 资产查询与借还历史
4. 账号和基础资料维护

视觉采用蓝色主操作、橙色风险提醒、白色内容面板和浅灰背景。所有状态均有文字和图形标记，不只依赖颜色。

## 2. 技术结构

```text
src/
  api/            REST 客户端和接口封装
  components/     页面标题、状态标签、指标卡
  constants/      状态文案与标签映射
  layouts/        应用框架和响应式导航
  router/         路由和角色守卫
  stores/         登录状态、通知状态、Socket.IO
  styles/         设计令牌与全局样式
  types/          API 类型
  views/          业务页面
```

Element Plus 使用按需组件加载。Vue 页面按路由动态加载，避免把全部业务页面打入首屏。

## 3. 角色导航

管理员：工作台、资产台账、借用申请、实际借还、通知待办、用户管理。

员工：工作台、资产借用、我的申请、我的借用、消息通知。

隐藏菜单只是体验层措施，实际权限仍由后端 JWT 和角色守卫决定。

## 4. 业务状态与操作

申请操作矩阵：

| 状态 | 管理员 | 员工 |
| --- | --- | --- |
| `PENDING` | 批准、驳回 | 取消 |
| `APPROVED` | 确认借出 | 只读 |
| `CHECKED_OUT` | 在借还页登记归还 | 只读 |
| `REJECTED` / `RETURNED` / `CANCELLED` | 只读 | 只读 |

资产操作矩阵：

| 状态 | 管理员可操作 |
| --- | --- |
| `AVAILABLE` | 编辑、维修、报废 |
| `MAINTENANCE` | 编辑、恢复可借、报废 |
| `RESERVED` / `BORROWED` | 编辑基础信息，只读状态 |
| `RETIRED` | 编辑基础信息，只读状态 |

## 5. 响应式与无障碍

- 桌面宽度 1024px 以上使用固定侧边栏。
- 窄屏使用顶部菜单按钮和抽屉导航。
- 720px 以下隐藏桌面表格，改为卡片列表。
- 手机输入框和主要按钮高度至少 44px。
- 所有表单使用可见标签，错误显示在对应字段附近。
- 页面切换后将焦点移动到主内容区域。
- 提供跳到主要内容链接、明显焦点框及减少动画支持。
- 图标按钮提供文字标签或可访问名称。

## 6. 数据反馈

- 初次加载使用表格或卡片区域 Loading。
- 空列表展示可理解的空状态。
- 提交期间按钮进入 Loading 并防止重复提交。
- 成功操作使用短时消息并刷新相关统计。
- 网络错误显示原因和可恢复提示，不将 `401`、`403` 混为同一种错误。

## 7. 实时通知

Socket.IO 负责及时提醒，不作为数据唯一来源。收到事件后：

- 刷新未读数量；
- 提示新通知或待办；
- 进入通知页时重新查询完整持久化数据；
- 断线重连后自动刷新 REST 数据。

管理员可以在“通知待办”页点击“发送通知”，选择全部启用账号或指定用户。发送成功后通知列表和未读数量会刷新；被选中的在线用户通过现有 WebSocket 实时收到提醒。

## 8. 首版外范围

前端不包含二维码、离线同步、外部门户推送、自动催还、批量多资产申请、移动端 App 和 Electron。
